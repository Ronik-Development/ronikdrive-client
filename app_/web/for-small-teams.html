No directory lookup before a person accepts.

An administrator selects only the role and access areas. RonikCloud returns a seven-day one-time code to share privately, without asking the administrator for the recipient's address or name.

  • Private handoffShare the invitation code through a trusted channel and verify its fingerprint separately when appropriate.
  • Explicit acceptanceAccess begins only after a signed-in recipient claims and accepts the invitation.
  • Immediate revocationIf the code is lost or sent to the wrong person, revoke the pending invitation before it is claimed.
  • Sensitive capabilityAnyone holding an active code can claim the selected access, so treat it as carefully as a private share link.

Share, discuss, review, and collect without dropping encryption.

Internal collaboration and external handoffs use different access paths, so you can keep teammates in the workspace and give clients a narrower way to send or receive one file.

Comments and review decisions

New comment text, review notes, display names, and mention addresses are encrypted on the device with the file key. Reviewers can approve or request changes.

External delivery

Create a password-protected encrypted copy with expiry and a request budget. Each request rechecks the creator's current membership and share permission.

External collection

File requests let a contributor encrypt an upload in the browser without being granted a place in the Business workspace.

Bounded activity history

Business history uses fixed action types and company-scoped pseudonymous member references. It does not duplicate file names, comments, or raw account identifiers.

Membership changes are treated as key events.

When membership, scope, group, or storage permissions change, RonikCloud clears decrypted Business keys, names, previews, and stale local work. A trusted authorized device then guides the team through any required encrypted-access reconciliation.

Open each affected space from an authorized trusted device and run Reconcile encrypted member access. Progress can pause and resume; completed items are skipped when work continues.

Operational boundary: The service still processes identifiers, permissions, review status, timestamps, notification routing, and limited activity records needed to run a shared workspace.

Small-team storage FAQ

How are shared Business folders encrypted?

A new shared Business folder uses a random folder key wrapped separately for each authorized member. Shared Business items do not fall back to the Personal password-derived key path.

How does a team invitation work?

An administrator chooses a role and access areas, then receives a seven-day one-time code to share privately. Access begins after a signed-in recipient claims and accepts the invitation.

What happens after team access changes?

Membership, group, shared-scope, and permission changes clear decrypted Business keys and stale local views. An authorized trusted device may then need to reconcile encrypted member access for affected spaces.
