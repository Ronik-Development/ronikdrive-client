Use boundaries your client can understand.

Instead of a permanently open link, choose how long access should last and how many encrypted-payload requests are reasonable. Send the password separately when the work is sensitive.

  • Password-protected copyThe filename, content type, and content stay within the client-held password boundary.
  • Expiry and request budgetDefine a narrow delivery window and watch request use from your link dashboard.
  • RevocationClose one link or use the emergency action to revoke every active link you own.
  • Clear caveatA recipient's already-downloaded copy cannot be recalled, so confirm who receives the link before sending.

Freelancer file workflow FAQ

Can a client send files without getting workspace access?

Yes. A file-request link lets a contributor submit through a public request page. The request details and uploaded file are encrypted on the contributor's device.

Can I ask a client to approve a delivered file?

File collaboration supports comments and a review status of pending, approved, or changes requested. Comment text and review notes are encrypted on the device with the file key.

Does encrypted collaboration hide every activity detail?

No. The service still sees identifiers, review status, timestamps, and notification routing needed to operate collaboration, while new comment text, review notes, display names, and mention addresses are encrypted on the device.
