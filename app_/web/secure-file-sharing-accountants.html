A client can send or receive without joining your workspace.

The public request and share pages are intentionally focused. They do not expose the owner’s folder tree, member permissions, or broader workspace history.

  • Bounded collectionSet a request expiry, maximum file size, and completed-upload limit, and close the request earlier when collection is complete.
  • Secret-bearing request linkThe private encryption key is carried in the URL fragment, which browsers do not send with the HTTP request. Treat the full link as sensitive.
  • Password-protected deliveryThe share password protects the encrypted filename, content type, and file content in the separate delivery copy.
  • Internal review stateAuthorized collaborators can keep encrypted new comments and review notes with pending, approved, or changes-requested status.

Security still depends on process.

Encryption is one control. Your firm also needs recipient verification, retention decisions, independent backups, device protection, and procedures that match the work and jurisdiction.

01

Verify the client channel

Confirm the intended recipient before sending a request or share. Deliver passwords separately when practical and close completed links.

02

Use the least access needed

Give an outside client a request or protected share instead of workspace membership when the task is only collection or delivery.

03

Keep an independent copy

Trash, rewind, and recovery tools help with supported records, but irreplaceable client material should also have an independent backup stored separately.

File sharing for accountants FAQ

Can a client upload documents without workspace access?

Yes. A file request provides a focused browser upload page without granting access to the owner’s workspace. Anyone holding the complete active request link may be able to submit, so it must be shared through a trusted channel.

Can an accountant limit a RonikCloud file request?

A file request has an expiry, maximum file size, and completed-upload limit, and its owner can close it earlier. These limits narrow the request but do not replace recipient verification or firm procedures.

Does RonikCloud certify accounting or privacy compliance?

No. RonikCloud does not claim that using the service makes a firm compliant with a law, professional rule, certification, or audit framework. Each organization must assess its own obligations, configuration, clients, devices, and workflows.

What information can RonikCloud still process?

The service still processes operational metadata including opaque identifiers, object sizes, timestamps, access relationships, request limits, review status, routing, account state, and limited security records. Network infrastructure can also observe connection data, timing, and traffic volume.
