Separate private storage, team access, and public handoffs.

Different audiences should receive different capabilities. RonikCloud uses personal protection, member-bound Business folder keys, and focused public transfer pages rather than treating every file interaction as the same kind of share.

  • Personal protected storageThe client encrypts protected file content, file names, and new folder labels before storage.
  • Small-team shared foldersNew Business folders use a random folder key wrapped separately for each authorized member.
  • Deliberate invitationsAn administrator chooses a role and access areas, then privately shares a time-bounded one-time invitation code.
  • External exchangePassword-protected encrypted share copies and browser-encrypted file requests give outsiders narrower access paths.

Protected content does not mean invisible infrastructure.

RonikCloud still needs object sizes, upload times, opaque references, parent-child and access relationships, storage routing, subscription state, and limited security records. Providers can observe connection data, timing, and traffic volume.

Dropbox encryption alternative FAQ

Is RonikCloud affiliated with Dropbox?

No. Dropbox is a third-party product. RonikCloud is an independent service and is not affiliated with or endorsed by Dropbox.

What does RonikCloud encrypt before storage?

The current RonikCloud client encrypts protected file content, protected file names, and new folder labels on the device before storage. App and browser traffic also uses HTTPS.

How are small-team shared folders protected?

New Business folders use a random folder key wrapped separately for each authorized member. Roles and access areas define permitted workspace actions, and membership changes clear stale decrypted Business state on the device.

Can RonikCloud import Dropbox automatically?

RonikCloud does not currently claim an automatic Dropbox importer. A cautious migration is to export or download data you control, verify the local copy, upload a representative set, test recovery, and keep the independent source until validation is complete.
