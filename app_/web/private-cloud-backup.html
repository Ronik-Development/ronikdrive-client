Private content with explicit operational boundaries.

Client-side encryption protects the substance of your files and private labels. Running a cloud service still requires a limited amount of operational information.

01

Protected on the device

File content, file names, and new folder labels are encrypted before storage. Optional image previews are also produced on the device within bounded limits.

02

Limited service metadata

The service still processes object sizes, upload times, opaque references, access relationships, keyed backup tags, storage routing, and account state.

03

Observable network activity

Infrastructure providers can still observe connection data, timing, traffic volume, and ordinary service logs. Client-side encryption does not hide every event.

Private cloud backup FAQ

What makes a RonikCloud folder backup private?

RonikCloud encrypts protected file content, file names, and new folder labels on the device before storage. Selected backup paths and raw comparison fingerprints stay in an authenticated encrypted device cache, while remote comparisons use an account-keyed integrity tag. Operational metadata and network observations are not hidden from all service infrastructure.

Can RonikCloud keep a selected folder up to date automatically?

Supported native builds can watch selected folders while RonikCloud is running, and supported release builds can continue through an enabled background worker. Scheduling depends on the build, device permissions, operating-system policy, and connectivity. A web browser cannot monitor a closed local folder.

Does RonikCloud replace an independent backup?

No. RonikCloud provides protected cloud storage, recovery tools for supported workspace records, and a user-held encryption recovery kit, but irreplaceable data should also have an independent backup stored separately.
