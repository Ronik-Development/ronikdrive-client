Let a client upload through a focused request page.

A file request is designed for one collection task. The request title, submitted filename, content type, and file body are encrypted on the contributor's device before storage.

  • Private URL fragmentThe encryption key travels in the private URL fragment, which browsers do not send as part of the HTTP request.
  • Claimed as one operationA completed encrypted upload is claimed in the same transaction that decrements the request's remaining allowance.
  • Owner-controlled requestThe owner can close a request when collection is finished instead of leaving it available indefinitely.
  • Sensitive capabilityAnyone who receives an active request URL may be able to submit, so send it through a trusted channel.

Keep the workspace original separate from the public link.

RonikCloud creates a separate encrypted share copy. The browser derives a proof from the password, the backend checks that proof before encrypted bytes leave storage, and the recipient's browser decrypts the protected file.

  • Password boundaryThe shared filename, content type, and file content stay inside the password-protected encrypted copy.
  • Defined lifetimeSet an expiry so the link is not intended to remain open forever.
  • Request budgetSet a limit on encrypted-payload requests and track its use from the owner view.
  • RevocationClose one link or revoke every active link you own. Already-downloaded recipient copies cannot be recalled.

Secure client file portal FAQ

Does a client need access to my RonikCloud workspace?

No workspace access is needed to use a public file-request page or receive a password-protected share copy. The client uses a focused browser page while the owner keeps control of the workspace. Links and passwords still need to be shared carefully.

Is the RonikCloud client portal white-label?

No. RonikCloud currently provides focused file-request and password-share pages rather than a custom-branded portal, customer relationship manager, or full project-management suite.

What controls are available for a delivered file?

A new protected share can have a password, expiry, and encrypted-payload request budget. Its owner can revoke the link or use an emergency revoke-all action. Revocation cannot recall a copy that a recipient already downloaded.

Does encrypted client exchange hide every activity detail?

No. The service still processes opaque file and account identifiers, timestamps, access relationships, review status, notification routing, request limits, and limited security records. Network infrastructure can observe connection data, timing, and traffic volume.
